## 2. Contexte du Projet

SENTRY est la plateforme de **Threat Intelligence et de Security Monitoring** du pilier
CyberillSec de l'organisation CYBERILL. Elle a pour but de :

1. Collecter des flux de Threat Intelligence (STIX, JSON, CSV, MISP) et de normaliser les
   indicateurs de compromission (IOC) : IPs, domaines, hashs, URLs ;
2. Surveiller les CVE en temps réel via l'API NVD et alerter sur les vulnérabilités critiques ;
3. Gérer le cycle de vie complet des incidents de sécurité ;
4. Fournir un dashboard SOC avec les KPIs ;
5. Exécuter des règles de threat hunting.

Le développement est découpé en **6 phases** sur **9 semaines** (J1 à J63) :
Foundation → Threat Feeds → CVE Tracker → Incident Management → SOC Dashboard → Threat Hunting.

### 4.3 `sentry/app/config.py` — Configuration de l'application

```python
from pydantic_settings import BaseSettings

class Settings(BaseSettings):
    database_url: str = "postgresql+asyncpg://sentry:sentry@localhost:5432/sentry"
    redis_url: str = "redis://localhost:6379/0"
    debug: bool = True
    app_name: str = "SENTRY"
    app_version: str = "0.1.0"
    log_level: str = "INFO"

    model_config = {"env_prefix": "SENTRY_", "env_file": ".env"}

settings = Settings()
```

**Explication :**
- `BaseSettings` de Pydantic permet de lire la configuration depuis **les variables
  d'environnement** ou un fichier `.env`. C'est une bonne pratique de sécurité : les
  mots de passe et URLs de connexion ne sont jamais codés en dur.
- `env_prefix = "SENTRY_"` : la variable `SENTRY_DATABASE_URL` écrasera la valeur par défaut.
- `database_url` : URL de connexion à PostgreSQL (`asyncpg` = driver asynchrone).
- `settings = Settings()` : instance unique (singleton) accessible partout dans le code.

### 4.4 `sentry/app/main.py` — Point d'entrée FastAPI

```python
from fastapi import FastAPI
from app.config import settings

app = FastAPI(
    title=settings.app_name,
    version=settings.app_version,
    docs_url="/docs" if settings.debug else None,
)

@app.get("/health")
async def health():
    return {"status": "ok", "version": settings.app_version, "app": settings.app_name}
```

**Explication :**
- `app = FastAPI(...)` : crée l'application web. `title` et `version` servent à la
  documentation automatique. `docs_url` n'est exposé qu'en mode debug (bonne pratique
  de sécurité : ne pas exposer la doc en production).
- `@app.get("/health")` : décorateur FastAPI. Il enregistre la fonction `health()`
  comme gestionnaire de la requête HTTP `GET /health`.
- La fonction renvoie un **dictionnaire Python** que FastAPI convertit automatiquement
  en **JSON**. C'est le "healthcheck" : un mécanisme standard pour vérifier que
  l'application est vivante (utilisé par Docker, les load balancers, les monitoring).

### 4.5 `sentry/app/database.py` — Connexion à la base de données

```python
from sqlalchemy.ext.asyncio import AsyncSession, create_async_engine, async_sessionmaker
from app.config import settings

engine = create_async_engine(settings.database_url, echo=settings.debug)
async_session = async_sessionmaker(engine, class_=AsyncSession, expire_on_commit=False)

async def get_session() -> AsyncSession:
    async with async_session() as session:
        try:
            yield session
        finally:
            await session.close()
```

**Explication :**
- `engine` : le "moteur" qui gère le pool de connexions à PostgreSQL.
  `echo=True` en debug affiche les requêtes SQL dans la console (utile pour débugger).
- `async_session` : une "usine" qui crée des sessions de travail.
  `expire_on_commit=False` : les objets restent utilisables après un commit.
- `get_session()` : **dépendance FastAPI**. Chaque requête HTTP qui a besoin de la
  base de données appellera cette fonction pour obtenir une session, et la fermera
  automatiquement à la fin. C'est le pattern d'injection de dépendances de FastAPI.

### 4.6 `sentry/app/models/base.py` — Base et mixin

```python
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column
from sqlalchemy import DateTime, func
from datetime import datetime

class Base(DeclarativeBase):
    pass

class TimestampMixin:
    created_at: Mapped[datetime] = mapped_column(
        DateTime(timezone=True), server_default=func.now()
    )
    updated_at: Mapped[datetime] = mapped_column(
        DateTime(timezone=True), server_default=func.now(), onupdate=func.now()
    )
```

**Explication :**
- `Base` : la classe mère de **tous** les modèles. SQLAlchemy scanne les classes qui
  héritent de `Base` pour créer les tables SQL automatiquement.
- `TimestampMixin` : un "mixin" = une classe de réutilisation. Toute table qui en
  hérite aura automatiquement deux colonnes :
  - `created_at` : date de création (remplie par la base : `server_default=func.now()`)
  - `updated_at` : date de dernière modification (`onupdate` la met à jour à chaque UPDATE)
- Avantage : on n'écrit les timestamps qu'une seule fois, toutes les tables les auront.

### 4.7 `sentry/app/models/user.py` — Modèle User

```python
from sqlalchemy import String, Boolean
from sqlalchemy.orm import Mapped, mapped_column
from app.models.base import Base, TimestampMixin
import uuid

class User(Base, TimestampMixin):
    __tablename__ = "users"

    id: Mapped[str] = mapped_column(
        String(36), primary_key=True, default=lambda: str(uuid.uuid4())
    )
    username: Mapped[str] = mapped_column(String(80), unique=True, nullable=False)
    email: Mapped[str] = mapped_column(String(255), unique=True, nullable=False)
    is_active: Mapped[bool] = mapped_column(Boolean, default=True)

    def __init__(self, **kwargs):
        if "id" not in kwargs:
            kwargs["id"] = str(uuid.uuid4())
        if "is_active" not in kwargs:
            kwargs["is_active"] = True
        super().__init__(**kwargs)

    def __repr__(self):
        return f"<User {self.username} ({self.email})>"
```

**Explication :**
- `__tablename__ = "users"` : nom de la table dans PostgreSQL.
- Chaque attribut `Mapped[...]` est une colonne de la table :
  - `id` : clé primaire, **UUID** (chaîne de 36 caractères) générée automatiquement.
    L'UUID est préféré à un simple compteur pour éviter les collisions et les
    énumérations (meilleure sécurité — on ne peut pas deviner les IDs).
  - `username` : chaîne de 80 caractères max, **unique** (pas de doublon), obligatoire.
  - `email` : chaîne de 255 caractères max, unique, obligatoire.
  - `is_active` : booléen, permet de désactiver un compte sans le supprimer.
- **Bug rencontré et corrigé :** `mapped_column(default=True)` ne fixe la valeur que
  lors de l'INSERT en base. En Python, `User(...).is_active` restait `None`.
  → Solution : constructeur `__init__` qui attribue les valeurs par défaut dès la
  création de l'objet. C'est plus prévisible pour les tests unitaires.
- `__repr__` : représentation lisible de l'objet (`<User admin (admin@cyberill.sec)>`),
  très utile pour les logs et le debug.

### 4.8 `sentry/tests/test_api.py` — Tests de l'API

```python
import pytest
from httpx import AsyncClient, ASGITransport
from app.main import app

@pytest.fixture
async def client():
    transport = ASGITransport(app=app)
    async with AsyncClient(transport=transport, base_url="http://test") as ac:
        yield ac

@pytest.mark.asyncio
async def test_health_endpoint(client):
    response = await client.get("/health")
    assert response.status_code == 200
    data = response.json()
    assert data["status"] == "ok"
    assert data["version"] == "0.1.0"
    assert data["app"] == "SENTRY"

@pytest.mark.asyncio
async def test_docs_enabled(client):
    response = await client.get("/docs")
    assert response.status_code == 200
    assert "swagger" in response.text.lower()
```

**Explication :**
- `@pytest.fixture` : une fonction "fixture" qui prépare l'environnement de test.
  Ici, elle crée un **client HTTP simulé** (`AsyncClient`) qui envoie des requêtes à
  l'application FastAPI **sans démarrer de vrai serveur** (via `ASGITransport`).
  C'est rapide et isolé.
- `test_health_endpoint` : envoie `GET /health` et vérifie :
  - que le code HTTP est **200** (OK) ;
  - que le JSON contient `status=ok`, `version=0.1.0`, `app=SENTRY`.
- `test_docs_enabled` : vérifie que la documentation Swagger (`/docs`) est accessible
  et contient bien le mot "swagger".
- **Pourquoi tester ?** Ces tests garantissent que si quelqu'un casse l'API (par
  exemple en modifiant le nom de l'endpoint), le problème est détecté immédiatement.

### 4.9 `sentry/tests/test_models.py` — Tests du modèle User

```python
import pytest
from app.models.user import User

class TestUserModel:
    def test_user_creation(self):
        user = User(username="admin", email="admin@cyberill.sec")
        assert user.username == "admin"
        assert user.email == "admin@cyberill.sec"
        assert user.is_active is True
        assert user.id is not None

    def test_user_repr(self):
        user = User(username="analyst", email="analyst@cyberill.sec")
        assert "analyst" in repr(user)
        assert "analyst@cyberill.sec" in repr(user)

    def test_user_default_active(self):
        user = User(username="readonly", email="ro@cyberill.sec")
        assert user.is_active is True

    def test_user_inactive(self):
        user = User(username="disabled", email="disabled@cyberill.sec", is_active=False)
        assert user.is_active is False

    def test_user_unique_id(self):
        user1 = User(username="u1", email="u1@test.com")
        user2 = User(username="u2", email="u2@test.com")
        assert user1.id != user2.id

    def test_user_timestamps(self):
        from app.models.base import TimestampMixin
        assert isinstance(User(), TimestampMixin)
```

**Explication :**
- Ces tests vérifient le **comportement du modèle sans base de données** (tests
  unitaires purs) : création, valeurs par défaut, unicité des UUID, représentation.
- `test_user_unique_id` : garantit que chaque utilisateur reçoit un UUID différent.
- `test_user_timestamps` : vérifie que le mixin de timestamps est bien hérité.
- **Pourquoi ces tests ?** Ils protègent les comportements essentiels du modèle.
  Si un développeur casse les valeurs par défaut, les tests échoueront et l'erreur
  sera corrigée immédiatement.
